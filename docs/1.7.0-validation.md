# WorldBinder 1.7.0 — verification and limits

Reviewed 28 October 2026. This summary distinguishes builds, automated data checks and actual Minecraft acceptance. Loader support is separate from support for arbitrary mod content. The full internal run history is maintained in the [development repository](https://github.com/Philiipp06/WorldBinder-DEVELOPMENT/blob/main/docs/1.7.0-validation.md); downloaded binaries, test worlds, logs and product-image preparation are not part of this source tree.

## Build and data checks

Use Java 25 and Node.js from the repository root:

```shell
./gradlew :build :neoforge:build :regressionTest :compileClientTestJava :neoforge:compileRuntimeTestJava --no-parallel
```

The 1.7.0 suite has **375 data assertions**, **2,147 matching English/German/French keys** and **six tests of the language auditor**. It covers old/current archives, project ownership, unchanged revisions, Recovery failures, container slot knowledge/merging, live filters, dimension/backend separation, replay barriers, legacy mappings, player progress and actual export read-back. Deliberately corrupt/missing caches must fail rather than become air; a valid recorded empty chunk remains valid.

Fabric and NeoForge are separate production packages. Test source sets and external Minecraft/replay/proxy/import programs are not embedded. The source layout and required versus generated files are described in [source-layout.md](source-layout.md).

## Replay playback acceptance

Ten completed combinations cover Fabric 26.1, 26.1.1, 26.1.2, 26.2 and 26.3 with **Flashback 0.43.6** and matching **ReplayMod 2.6.28** builds. Each creates an original recording, captures real playback, protects newer data during a backward seek, restarts Minecraft, resumes without the original server, exports and opens the resulting vanilla world. The previous archive remains unchanged.

All ten use the same Fabric artifact `258d0bd953b5433f5252e1aaa2ddd23d2d775322ad7d6c78fd2df502dee9fb4d`. Compared with the current artifact, only the 1.13-specific compatibility warnings and the two language resources changed; replay/capture code and world/player conversion are byte-identical. The ten runs were not repeated after that warning-only change. Replay integration is optional and Fabric-only; no native NeoForge build of those upstream mods is promised. Direct replay-file import is not included.

Use `scripts/qa/download-replay-tools.mjs` and `scripts/qa/run-replay-matrix.ps1`. Exact-version source fixtures are required; a fresh successful recording is required before restart acceptance.

## Known limits

- **Minecraft 1.13:** it cannot retain map locks; using the map can replace received Map-Art with terrain. Changed chunks also remained dark in the native lighting comparison. Neither visual case is claimed as passed. Export review/report warns explicitly; the complete original data stays in the archive for a newer target or target-world repair.
- **Player progress across versions:** verified play-time renames preserve exact ticks and conflicting aliases fail. Other unsupported statistic/advancement IDs and criteria are retained with an explicit compatibility warning, rather than invented equivalents.
- **Generation and custom dimensions:** Void/Flat generation for recorded Nether/End dimensions can show Minecraft's experimental-settings prompt. A tested custom dimension with a vanilla type does not certify foreign registries, generators or portal mods.
- **Completeness:** only received data can be reconstructed. A readable export can still lack inventories, maps or original section data. File validity and capture completeness are separate results.
- **Scope:** these results do not certify every modpack, server/plugin combination, HUD/theme choice, long public-server session or actual power-loss scenario. A source build and automated data tests do not replace native gameplay acceptance.
